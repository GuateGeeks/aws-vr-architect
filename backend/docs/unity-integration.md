# Integración con el proyecto VR existente

Este backend acepta la salida de `JsonUtility.ToJson(Architecture)` del proyecto vecino: `schemaVersion`, `region`, `nodes` y `links`; `kind` es el enum numérico 0–6. Conserva IDs de nodos. No envíes código ni ARNs. `position` y `state` se ignoran; el backend calcula estado real de CloudFormation.

La versión 0.3.0 de `GuateGeeksAWSVR` implementa `AwsCloudApi` con UnityWebRequest y conserva `MockCloudApi` como modo inicial. La compilación Quest habilita Internet. El panel móvil **CONEXIÓN AWS** cambia de proveedor solamente cuando el operador conecta una sesión. Consulta [la guía operativa de Unity](../../GuateGeeksAWSVR/Documentation/Cloud-Integration.md) para compilar, provisionar credenciales por USB, recuperar diseños y validar la integración.

`tools/connect_quest.py` lee los outputs de CloudFormation y el secreto mediante el perfil del operador; transmite un bootstrap temporal por stdin de adb. Unity lo consume y elimina al pulsar **Conectar AWS (USB)**. Caduca en 60 segundos y el script elimina el archivo si no se consume. No crea infraestructura. Las credenciales no se incluyen en el APK, PlayerPrefs ni diseños guardados. El archivo existe brevemente en texto plano en el visor de desarrollo: usa USB y dispositivos de confianza; una desconexión puede impedir su limpieza, aunque vencido no se puede usar para conectar.

1. Configura URL HTTPS, usuario y contraseña en tiempo de ejecución por un canal de operador. No guardes la contraseña en PlayerPrefs ni en el APK. No desactives validación TLS.
2. `Connect`: GET `/v1/session` con cabecera `Authorization: Basic <base64(UTF8(usuario:contraseña))>`; comprueba la región devuelta.
3. `Deploy`: valida primero y manda `{ "deploymentId":"1", "architecture": <snapshot> }` a POST `/v1/deployments`. Guarda el slot y `stackId`; no marques éxito al recibir 202. Verifica `graphHash` contra el fingerprint devuelto por validación, incluyendo la recuperación después de un timeout. El backend ahora devuelve ese campo tanto al crear como al consultar el estado.
4. Consulta GET `/v1/deployments/1` cada 3 segundos. Relaciona `nodes[].resourceId` con los IDs del snapshot. Mapea `CREATE_IN_PROGRESS` a Provisioning, `CREATE_COMPLETE` a Ready y estados FAILED/ROLLBACK a Failed. Considera éxito total **únicamente** si `success:true`. Los nodos que aún no aparezcan permanecen Provisioning.
5. `Invoke`: POST `/v1/deployments/1/events` con `resourceId` del nodo de entrada; presenta 202 como evento aceptado, no como procesamiento completado. Elimina latencias ficticias del mock en modo real.
6. `Disconnect` termina la sesión local y detiene polling; no cancela CloudFormation ni borra recursos. La cancelación del mock no existe en AWS. En la versión 0.3.0 la limpieza se realiza desde `tools/demo.py delete` por el operador, no desde el visor. El endpoint DELETE con `purge=true` elimina datos; si `retryDelete:true`, se repite DELETE, en otro caso se consulta hasta 404. Un futuro botón de borrado debe exigir confirmación explícita de los datos/slot a eliminar.

`simulateFailure` pertenece al mock: el adaptador real debe rechazarlo localmente o deshabilitar ese control. Las validaciones visuales de Unity permiten REST API y algunos fan-outs que este backend no implementa; usa `/v1/catalog` y la tabla del README para deshabilitarlos en modo real y muestra cualquier 400 del servidor antes de desplegar.

Ante timeout de creación no elijas otro slot: consulta el mismo para recuperar la operación. Al recibir 401 vuelve a solicitar credenciales; ante 403 revisa IP/red del evento; ante 429 aplica backoff con jitter. La identidad de servicio es compartida, por lo que un segundo frontend puede ver/borrar esos mismos slots. No uses este contrato como separación de tenants.

La API está preparada para clientes nativos. No habilita CORS para aplicaciones web; ese sería un cambio explícito con orígenes autorizados. La especificación [OpenAPI](openapi.yaml) describe las rutas y DTOs para otros clientes. `tools/export_unity_contract.py` genera fixtures ejecutando las rutas reales con clientes AWS sustituidos; los tests Unity usan esas respuestas sin conexiones externas. La integración completa con un backend desplegado sigue pendiente hasta que exista un endpoint.
